# PNG chunk map

Written before the PNG stripper (Council PRE-BUILD condition 1). The code in `src/lib/metadata/png/` must match this table.

## How a PNG file is laid out

An 8-byte signature, then a list of chunks, ending with `IEND`:

```
89 50 4E 47 0D 0A 1A 0A          signature
<length: 4 bytes, big-endian> <type: 4 ASCII letters> <data: length bytes> <CRC: 4 bytes>
```

Compared with JPEG this is friendlier in two ways. Every chunk carries its own length, so there is no scan-data hunting. And every chunk has a CRC-32 over its type and data, so damage is detectable.

The case of the type letters is meaningful:

- first letter uppercase = **critical** (a decoder must understand it: `IHDR`, `PLTE`, `IDAT`, `IEND`)
- first letter lowercase = **ancillary** (safe to drop; this is where metadata lives)

The catch: the CRC covers the chunk, so any chunk we write ourselves needs a correct CRC-32. We copy kept chunks byte for byte (CRC included), and compute a CRC only for the one chunk we build.

## Rule: default deny

Same as JPEG: keep a short allow-list, drop everything else. An unknown ancillary chunk is removed. An unknown **critical** chunk (uppercase first letter, not in this table) means we cannot safely understand the file, so it is rejected as corrupt rather than guessed at.

## Chunk table

| Chunk | Name | Action | Why |
|---|---|---|---|
| `IHDR` | Header | keep | Width, height, bit depth, colour type. Must be first |
| `PLTE` | Palette | keep | Colours of an indexed image |
| `IDAT` | Image data | keep, byte for byte | The pixels (one or several chunks) |
| `IEND` | End | keep | Must be last |
| `tRNS` | Transparency | keep | Without it, transparent pixels become opaque |
| `gAMA` `cHRM` `sRGB` `cICP` | Colour description | keep | Affect how colours display; not identifying |
| `sBIT` `bKGD` `hIST` | Rendering hints | keep | Significant bits, background colour, palette histogram |
| `pHYs` | Pixel size | keep | Pixels per unit (DPI). A display hint, not identifying |
| `acTL` `fcTL` `fdAT` | Animation (APNG) | keep | Without them an animated PNG becomes a still |
| `iCCP` | ICC colour profile | keep (switch can remove) | Colours shift without it |
| `eXIf` | EXIF | **replace** | Remove everything. If the original held a valid Orientation (1 to 8), write a new `eXIf` chunk with only that tag |
| `tEXt` `zTXt` `iTXt` | Text | remove | Author, copyright, software, creation time, comments, and XMP (stored in `iTXt` under the keyword `XML:com.adobe.xmp`) |
| `tIME` | Last modified | remove | A timestamp |
| `sPLT` `dSIG` and any other ancillary | Other | remove | Not needed to display; unknown means removed |
| any other critical chunk | Unknown critical | reject | Cannot be understood safely |
| anything after `IEND` | Trailing data | remove | Appended payloads |

## Orientation, in bytes

PNG stores EXIF bare, with no `Exif\0\0` prefix: the chunk data is the TIFF structure itself. The block we write is 26 bytes, so the whole chunk is 4 + 4 + 26 + 4 = 38 bytes:

```
00 00 00 1A                      data length: 26
65 58 49 66                      type "eXIf"
4D 4D 00 2A  00 00 00 08         byte order "MM", magic 42, IFD0 at offset 8
00 01                            one entry
01 12  00 03  00 00 00 01  00 06 00 00     Orientation, SHORT, count 1, value 6
00 00 00 00                      no next IFD
<CRC-32 of "eXIf" + the 26 data bytes>
```

It goes right after `IHDR`. The PNG rules only forbid placing it between `IDAT` chunks.

Some old writers (ImageMagick) store EXIF as text under `Raw profile type exif`. That is a text chunk, so it is removed and its Orientation is not carried over. Modern viewers read `eXIf`.

## What "identifying" means for the verifier

After stripping, the re-read check allows only:

- chunks from the keep rows above
- `iCCP` unless removal was requested
- at most one `eXIf`, holding exactly one tag: Orientation
- zero bytes after `IEND`

Anything else is a finding, including chunks this file does not list.

## Image data check

"Image data unchanged" means these chunks are byte-identical before and after: `IHDR`, `PLTE`, `tRNS`, `IDAT`, and the APNG chunks `acTL`, `fcTL`, `fdAT`.
